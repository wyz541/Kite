# macOS 分栏搜索

## 结论

macOS 每个分栏标题栏提供搜索按钮。
搜索在当前分栏目录及其子目录中执行。
搜索结果保留在触发搜索的分栏内。
Windows 使用同一 Core 搜索入口和排序规则。

## 交互

1. 点击分栏标题栏的搜索按钮，或在分栏上直接输入字符。
2. 输入即搜索。每次输入先做本地过滤。
3. 停止输入 180 毫秒后，仅在本地结果不能保证完整时执行递归搜索。
4. 按 Enter 打开当前选中的结果。没有选中时打开第一条结果。
5. 搜索仍在运行时按 Enter 立即执行递归搜索。
6. Command+Enter 或 Ctrl+Enter 跳过选中结果，立即重新搜索。
7. 按 ↓ 或 ↑ 在结果之间移动选择。
8. 按 Esc 或关闭按钮退出搜索。
9. 关闭搜索后恢复原目录列表。

分栏搜索显示在分栏标题栏下方的独立一行。
标题栏保持完整，搜索按钮在搜索开启时呈按下状态。
搜索结束时不自动选中结果。
按 Enter 打开当前选中结果；没有选中时打开第一条结果。
按 ↓ 从第一条结果开始选择。

同一时间只保留一个打开的搜索栏。
切换到另一分栏搜索时，Kite 关闭前一搜索栏。

## 本地优先

1. 上一个结果集完整时，如果新查询包含旧查询，直接在内存中收窄，不发起目录遍历。
2. 无法复用完整结果时，先显示当前目录内匹配的项目，作为递归搜索的预览。
3. 上一个结果集被截断时，本地收窄只作为预览，仍然执行递归搜索。
4. 输入期间保留上一次结果；新查询的搜索结果返回后替换。
5. 递归搜索完成后替换预览结果。

## 数据流

1. SwiftUI 将目录路径和搜索词传给 Rust Core。
2. Rust Core 使用并行目录遍历读取子目录。
3. Rust Core 按匹配度排序后返回最多 1000 个匹配项目。
4. SwiftUI 将结果写入对应分栏，不按分栏排序重排结果。
5. 分栏筛选仍然生效。
6. 分栏分组规则对搜索结果生效。组内保持匹配度顺序。

## 排序

1. 完全匹配。
2. 名称前缀匹配。
3. 分隔符之后的匹配。
4. 其他子串匹配。
5. 同一匹配层级内，目录深度浅的项目优先。
6. 再按匹配位置和名称长度排序。
7. 以上条件相同时，按传入的排序规则决定次序。macOS 的 Core 入口固定使用名称升序。

搜索结果行显示相对目录。
macOS 的完整路径在悬停提示中。

搜索期间排序按钮不可用，搜索结果顺序固定为匹配度顺序。
显示规则菜单仍可使用，可切换筛选和分组。
分组标题显示在结果之间，可折叠；折叠后该组结果不显示。

## 取消与状态

- 新搜索取消正在运行的旧搜索。
- 关闭搜索取消正在运行的任务。
- 切换页签取消当前搜索任务。
- 搜索结果为空且搜索仍在运行时显示“搜索中…”。
- 搜索完成后才显示“无搜索结果”。
- 搜索结果显示结果数量和截断状态。
- 崩溃或目录读取失败不会覆盖原目录列表。
- 文件操作触发刷新时，活动搜索按当前查询重新执行。
- 其他程序改动目录时，结果在下次输入或刷新后更新。

## 范围

当前搜索只匹配项目名称。
搜索不进入隐藏目录。
搜索不进入生成目录，例如 `node_modules`、`target`、`build`、`dist`、`.git`、`.svn`。
搜索分栏本身就是生成目录时，仍然搜索该目录的直接内容。
最多返回 1000 个结果，超过时显示截断状态。

## 预览位置（Windows）

1. 搜索栏所在的列决定预览归属。
2. 搜索栏位于最后一列时，预览占用最右侧同层空间，参与列布局。
3. 搜索栏位于非最后一列时，预览以浮层形式覆盖右侧列，不压缩右侧列宽度。
4. 打开非最后一列的搜索时，横向视图滚动到该列。
5. 在搜索列选中文件不截断右侧列。
6. 关闭搜索后浮层消失，右侧列恢复完整宽度。

## 全局工具栏搜索

工具栏提供全局搜索入口。
全局搜索在活动页签的当前目录中执行。
搜索按钮打开工具栏输入框。
菜单命令“搜索当前文件夹”使用 Command+Shift+F。
按 Enter 开始搜索。
按 Esc 或关闭按钮退出搜索。
搜索结果替换分栏区域。
结果行显示项目名称和相对目录。
双击文件夹打开该文件夹。
双击文件使用系统默认程序打开。
关闭搜索后恢复当前分栏。
切换页签或导航到其他目录会取消全局搜索。
