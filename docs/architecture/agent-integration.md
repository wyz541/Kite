# Kite Agent 集成架构

## 结论

Kite 是 Agent 宿主和文件上下文桥，不是模型运行时。

Agent 的 UI、CLI 和 MCP 入口统一通过 [Core API 与多端外壳](core-api.md) 的 `CoreApi` 边界调用业务逻辑。

- 外部 Agent 负责模型推理、认证和自身工具执行。
- Kite 负责配置、上下文快照、ACP 会话、权限确认、结果阅读和本地审计。
- Windows 与 macOS 共享 Rust Core 的配置与会话语义，各自实现原生界面。
- P0 默认只读。任何写入、命令执行或高风险工具调用都必须先展示影响并获得用户确认。

## 产品边界

Kite 不提供以下能力：

- 模型推理后端。
- 自动下载、升级或登录外部 Agent。
- 对任意 CLI 进程的通用沙箱。
- 多 Agent 并行对比或团队配置同步。
- 自动执行 Agent 建议的 shell 命令。
- 在没有 diff 和明确确认的情况下修改文件。

外部 Agent 的进程权限最终由操作系统、Agent 自身和用户授权共同决定。
如果某个 Agent 无法被 Kite 强制约束，界面必须显示“权限由 Agent 自身管理”，不能展示虚假的只读保证。

## 模块边界

### Rust Core

Rust Core 负责：

- `AgentProfileStore`：配置、迁移、校验、默认 Profile 和原子持久化。
- `AgentContext`：主目标、附加路径、工作目录、文件类型和 Git 状态。
- `AgentSession`：进程启动、ACP 握手、流式事件、取消、超时和清理。
- `AgentDiagnostics`：版本、协议、能力、连接结果、配置路径和脱敏日志。
- `AgentSessionRestore`：Agent、模型、工作目录、上下文、对话和窗口状态。
- `AgentAudit`：不含提示正文、密钥和完整文件内容的本地审计记录。

Core 不依赖 GPUI、SwiftUI 或 AppKit。

### Windows

Windows 前端负责：

- GPUI Agent 设置页。
- 右侧 Agent 栏与独立 Agent 窗口。
- 右键 `AgentMenuProvider`。
- Windows 系统钥匙串和本地文件入口。
- 使用 `CREATE_NO_WINDOW` 启动 Agent 子进程。
- 取消或关闭窗口时清理完整进程树。

### macOS

macOS 前端负责：

- SwiftUI Agent 设置页。
- SwiftUI/AppKit Agent 栏与独立窗口。
- 原生右键菜单中的 Agent 子菜单。
- macOS Keychain 和本地文件入口。
- 使用进程组清理 Agent 及其子进程。

## 配置

Agent 配置保存在用户本地数据目录下的 `agent.json`。

配置包含：

- `schema_version`。
- Profile 列表。
- 默认 Profile。
- 接入方式、可执行文件、参数、模型和工作目录策略。
- 权限模式、启动/空闲/总超时和输出上限。
- 凭据引用，不保存明文 token 或密码。

写入规则：

- 使用临时文件、同步和原子替换。
- 保留上一版本备份。
- 主文件损坏时回退到备份或安全默认值。
- 文件大小和 Profile 数量均有上限。
- 未知 schema 版本产生明确警告，不阻塞 Kite 启动。

Kite 不自动扫描、导入或覆盖 Agent 原生配置。
预设只填充接入元数据，认证继续由 Agent 自己的登录流程完成。

## 内置预设

首批仅列出可验证的 ACP 接入：

### Claude Code ACP

- 适配器：`@zed-industries/claude-code-acp`。
- 验证版本：`0.16.2`。
- 用户需先安装适配器并完成 Claude Code 原生认证。

### Codex ACP

- 适配器：`@zed-industries/codex-acp`。
- 验证版本：`0.16.0`。
- 用户需先安装适配器并完成 Codex 原生认证。

未验证的供应商不进入内置列表。
自定义接入继续保留。
预设不能包含 API key、密码或其他明文凭据。

## ACP 会话

首选传输是 ACP 兼容的 JSON-RPC over stdio。

典型顺序：

1. 启动外部 Agent 进程。
2. 发送 `initialize`，协商协议版本和能力。
3. 发送 `session/new`，传入绝对工作目录和 MCP 配置。
4. 发送 `session/prompt`，携带文本和 `resource_link` 上下文。
5. 接收 `session/update`，映射为消息、思考、工具、计划和状态事件。
6. 接收 `session/request_permission`，等待用户选择。
7. 收到 `session/prompt` 响应后进入空闲状态。

Windows Agent 面板在同一轮询任务中等待 session 进入 `Ready` 后再发送 `session/prompt`，因此不会阻塞 UI 线程。
内层独立窗口按钮会等当前 `AgentPanel` update 完全退出后再创建共享窗口，避免同一实体的 double lease。

Kite 只向 Agent 广告它实际实现的客户端能力。
P0 不广告文件写入或终端执行能力。
Agent 自己仍可能通过其原生工具请求权限，因此界面必须显示真实权限边界。

取消：

- 运行中取消先发送 `session/cancel`。
- 所有待处理权限请求以 `cancelled` 结果返回。
- 宽限期后仍未结束，则终止完整进程树。
- 每条错误路径都必须清理子进程和读取线程。

## 上下文

默认上下文是打开 Agent 时生成的固定快照。

- 切换目录不会静默改变已固定上下文。
- 用户必须显式开启“跟随当前选择”。
- 多选路径完整保留。
- 发送前始终展示 Agent、模型、工作目录、上下文数量和权限模式。
- 路径失效时显示移除、定位或重新选择入口。

上下文使用 ACP `resource_link` 发送。
大文件不在右键或菜单阶段预读。
Agent 需要文件内容时，应使用自己的工作区工具或权限请求流程。

## 结果与权限

结果操作：

- 复制当前可恢复内容。
- 在分栏中定位引用文件。
- 用默认应用打开引用文件。
- 插入文本编辑器。
- 另存为文件。

结构化修改：

- 显示受影响路径、增删行数、目标写入位置和覆盖风险。
- 展示 unified diff。
- 用户选择“应用”“另存为”或“放弃”。
- 应用前重新校验文件哈希；文件已被外部修改时拒绝覆盖并重新确认。

Kite 只把显式结构化结果解释为文件修改；普通文本回答不会自动变成补丁。
应用前必须重新校验目标文件哈希，任何外部变化都要求重新确认。
详细写入边界见 [Agent 结果审核与写入](agent-result-review.md)。

权限请求：

- “仅本次允许”。
- “本任务允许”。
- “拒绝”。

拒绝结果必须结构化返回 Agent，不能让任务静默卡死。
Kite 不自动执行 Agent 提出的 shell 命令，最多展示为可复制文本。

## 会话恢复

会话恢复是可选能力。

保存内容：

- Agent Profile 和模型。
- 工作目录。
- 固定上下文快照。
- 对话消息和草稿。
- 右侧栏或独立窗口状态。
- 窗口尺寸。

恢复不会阻塞 Kite 启动。
路径失效时：

- 保留其余对话和配置。
- 标记缺失路径。
- 提供重新定位或移除入口。
- 在修复前不自动发送新提示。

配置和会话只保存在本机。
审计日志不记录提示正文、助手回答正文、密钥或完整文件内容。

## 诊断

Agent 诊断页显示：

- 配置路径和会话路径。
- Agent 名称、命令解析结果和版本。
- ACP 协议版本和能力。
- 连接测试状态和延迟。
- 最近错误。
- 脱敏日志。

日志脱敏覆盖：

- Bearer token。
- API key、token、secret 和 password 形式的值。
- URL 内嵌用户名和密码。
- 常见 `sk-*` 密钥。

原始 stderr 不直接作为回答内容展示。
诊断日志由用户主动打开。

## 测试夹具

`kite-agent-fixture` 是跨平台 ACP 测试进程。

覆盖场景：

- 正常启动、握手和流式输出。
- 流式 Markdown 和代码块。
- 权限请求与允许/拒绝响应。
- 取消。
- 启动、空闲和总超时。
- 超大帧和超大总输出。
- Agent 错误和认证错误。
- stderr 密钥脱敏。
- 子进程树清理。
- 失败后新会话重试。

自动化测试不依赖真实模型、网络或用户凭据。

## 性能基线

Agent 性能场景记录：

- 启动到 ACP Ready 的延迟。
- Agent 子进程常驻内存。
- 流式输出吞吐。
- 长对话追加和滚动准备耗时。

性能基线用于发现回归，不作为不同 Agent 能力的排名。
真实 Agent 的启动时间和内存取决于其运行时、模型和认证状态。

## 平台对等

Windows 与 macOS 必须具备相同语义：

- 预设和配置校验。
- 右键入口和预填行为。
- 固定上下文与跟随选择。
- 流式状态和取消。
- 权限确认和拒绝结果。
- 诊断错误分类。
- 脱敏规则。
- 会话恢复和路径修复。

渲染器、系统钥匙串和进程清理实现保持平台原生。

## 已知限制

- Kite 不保证外部 Agent 的判断正确。
- 普通 CLI 无法被 Kite 强制只读。
- Agent 原生配置、登录状态和额度由 Agent 自己管理。
- P0 不自动下载 Agent。
- 长对话恢复受本地会话文件大小和消息数量上限约束。
- 本期不做多 Agent 并行对比、云同步或团队共享配置。
