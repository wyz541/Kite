{{项目名}} × RCSM 递归能力切片地图 v1.0
	00 模型说明
		模型名称
			RCSM：Recursive Capability Slice Map
			中文：递归能力切片地图
		模型定位
			RVSS-inspired：吸收递归拆解和垂直切片思想
			面向 XMind：强调可读、可量化、可定位、可追踪
			不是纯 RVSS：允许横向约束和证据节点存在
		四层结构
			L0 全局上下文：项目目标、边界、平台和约束
			L1 垂直切片：按用户结果和端到端效果切分
			L2 横向约束：跨切片的架构与工程关注点
			L3 能力卡与证据：语义、契约、数值、代码、风险、验收
		结构公式
			System = Context + Σ(VerticalSlice) + CrossCuttingConstraints
			VerticalSlice = Overview + Flow + CapabilityCards + Evidence
			CapabilityCard = Semantics + Contract + Implementation + Metrics + Risk + Evidence
		递归规则
			满足独立触发、独立边界、独立契约、独立证据时，可以成为一个切片
			父切片必须由子切片组合形成，不能只是分类标签
			能由一张能力卡完整说明时，停止递归
			无法独立验证时，继续拆或标为未知项
		节点类型约定
			[CTX] 全局上下文
			[VS] 垂直切片
			[CAP] 能力卡
			[METRIC] 数值与参数
			[CODE] 代码关键词或代码锚点
			[RISK] 失败、取消、恢复、未知项
			[EV] 测试、文档、观测证据
		命名规范
			垂直切片：VS-01、VS-01.02、VS-01.02.01
			横向约束：HX-01、HX-02
			能力卡：CAP-VS01-01
			数值：M-...
			代码：CODE-...
			证据：EV-...

		叶子节点有效性
			有效：可解释的能力、可验证的数值、可定位的代码、可复查的证据
			有效：明确标注的未知项或风险
			无效：只有组件名
			无效：只有文件路径
			无效：只有结论，没有边界或证据
		来源原子化规范
			基本规则：一个叶子只表示一个来源
			来源类型：Rust 依赖 / 系统 API / UI 组件 / 项目代码 / 测试 / 文档 / 脚本
			推荐结构：来源类型 → 单个来源 → 用途或说明
			禁止结构：一个叶子用顿号或逗号堆叠多个来源
			文件来源：一个叶子只放一个文件路径
			依赖来源：一个叶子只放一个 crate / package / library
			系统 API：一个叶子只放一个 API 或接口族
			文档来源：一个叶子只放一篇文档
			例外：一个来源下的用途说明可以作为其子节点
		代码布局规范
			一个代码叶子只放一个 token、类型、API 或步骤
			关键词块：按分号或独立 token 拆行
			过程块：按箭头拆行，后续步骤以 → 开头
			样式：等宽字体、左对齐、浅色代码背景
			... 表示省略重复参数、分支和中间步骤
			禁止把关键词和过程写在同一个长段落

	06 复用操作手册
		Step 1：创建全局上下文
			替换 {{项目名}}
			填写产品边界、平台和约束
		Step 2：识别垂直切片
			按用户结果切，不按代码层切
			每个切片必须端到端
		Step 3：递归拆子切片
			满足递归规则才继续
			不要为了树好看而拆
		Step 4：建立横向约束
			把架构、异步、安全、测试抽到 HX 分支
		Step 5：填充能力卡
			每张卡至少回答语义、契约、实现、数值、风险、证据
		Step 6：挂代码与数值
			... 省略细节，保留 API、类型、关键顺序
		Step 7：写验收
			每条能力至少有 1 个可复查证据
		Step 8：标记未知
			不能确认的值写未知，不猜测
		Step 9：质量门检查
			逐项检查 07 质量门
		建议规模（可按项目调整）
			一级垂直切片：建议 3–9 个
			单个切片能力卡：建议 3–12 张
			单张能力卡：建议 10–15 个字段
			单卡叶子节点：建议不超过 20 个
			超出时优先拆子切片或拆 Sheet
		XMind 使用建议
			默认展开：根 → 一级主题 → 二级主题
			能力卡默认折叠，只展开“语义 / 数值 / 代码 / 验收”之一
			先填垂直切片，再补横向约束
			未知项使用 [?] 标记，不删除
			大型项目按业务域拆多个 Sheet，共用 00 模型说明
	07 质量门
		结构检查
			[ ] 一级主题中垂直切片与横向约束分开
			[ ] 每个切片有明确边界
			[ ] 递归有终止条件
		语义检查
			[ ] 不存在裸名词
			[ ] 每个能力能解释“能做什么”
			[ ] 每个能力说明在本项目中的用法
		契约检查
			[ ] 输入/输出明确
			[ ] 前置条件明确
			[ ] 不变量和边界明确
		数值检查
			[ ] 有硬编码值或实测值
			[ ] 无固定上限时明确标注
			[ ] 性能数值注明版本和环境
		代码检查
			[ ] 有核心 API/类型/字段
			[ ] 有缩略调用过程
			[ ] 有可定位的代码锚点
		验收检查
			[ ] 有测试/日志/截图/观测之一
			[ ] 失败和取消路径可验证
			[ ] 未知项有责任人/下一步
		追踪检查
			[ ] 能力 ID 可回链切片
			[ ] 横向约束有引用
			[ ] 证据可回到来源
		来源检查
			[ ] 一个叶子只对应一个依赖/API/文件/文档
			[ ] 来源按类型分组
			[ ] 没有用顿号或逗号堆叠多个来源
			[ ] 代码文件路径可定位
			[ ] 文档路径可定位
			[ ] 版本号与来源名称一致
		代码布局检查
			[ ] 关键词按 token / 类型 / API 分行
			[ ] 过程按箭头分行
			[ ] 代码节点使用等宽字体
			[ ] 关键词和过程没有塞进同一段落
			[ ] 长表达式可以换行，但没有混入无关步骤
