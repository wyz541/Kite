	01 项目定位与边界
		主题概览
			一句话定位
				先看清 Kite 是什么，以及为什么它不是一套 UI 跑遍所有平台。
			学完能回答
				哪些能力由两端共享？Windows 和 macOS 各负责什么？
		产品定位
			本地优先的跨平台原生文件管理器
			分栏导航、预览、搜索、文件操作在同一工作区
		架构定位
			共享 Rust Core
			Windows：Rust + GPUI
				Windows
					作用：目标操作系统
					Kite 中：Windows 10/11 x64
				Rust
					作用：实现语言和跨平台核心
					Kite 中：Core、GPUI 前端和系统桥
				GPUI
					作用：Rust 原生桌面 UI 框架
					Kite 中：Windows Kite 界面
			macOS：SwiftUI + AppKit
				macOS
					作用：目标操作系统
					Kite 中：macOS 13+ Apple Silicon
				SwiftUI
					作用：声明式原生界面
					Kite 中：窗口、分栏、搜索和设置
				AppKit
					作用：调用 macOS 系统能力
					Kite 中：Finder、Quick Look、菜单和剪贴板
			两端共享领域能力，不共享 UI 渲染器
		设计原则
			macOS 作为视觉与交互基准
			Windows GPUI 实现同一产品语义
			路径先于装饰，状态先于品牌，反馈先于动画
			可逆性优先：历史、回收站、会话恢复、确认
		核心能力来源
			设计文档
				README.md
				docs/design/manifesto.md
				docs/architecture/platforms.md
			项目配置
				Cargo.toml
		能力说明
			Rust Core
				是什么
					一个不依赖任何 UI 框架的 Rust 业务核心，输出 rlib、staticlib 和 cdylib。
				能做什么
					负责文件、搜索、VCS、会话、Agent、更新等业务规则和副作用。
				在 Kite 中的用法
					Windows GPUI 直接依赖它；macOS SwiftUI 通过 UniFFI 调用它；CLI 和 MCP 也复用它。
				一句类比
					同一间后厨，给不同前厅供应同一套菜。
				项目关键数值
					顶层 Rust 模块：33 个 pub mod
					产物类型：rlib / staticlib / cdylib，共 3 种
					跨端复用入口：GPUI、SwiftUI、CLI、MCP，共 4 个外壳
				核心代码关键词
					关键词
						pub mod fs/git/agent/search/...
						crate-type = [rlib, staticlib, cdylib]
						uniffi::setup_scaffolding!()
					过程
						领域模块 ...
						→ lib.rs 导出 ...
						→ UI/Swift/CLI/MCP 复用
			原生 UI Shell
				是什么
					每个平台用符合系统习惯的界面技术实现窗口、菜单、布局和交互。
				能做什么
					负责展示、输入、焦点、主题和系统交互，不复制核心业务状态机。
				在 Kite 中的用法
					Windows 用 Rust + GPUI；macOS 用 SwiftUI + AppKit。
				一句类比
					两套装修风格不同的前厅，共用同一后厨。
				项目关键数值
					平台 UI：Windows GPUI + macOS SwiftUI/AppKit，共 2 套
					Windows 窗口文件：14 个 *window*.rs
					Render 实现：18 个
				核心代码关键词
					关键词
						#[cfg(windows)] mod app/tabs/...
						gpui_kit::application()
						SwiftUI + AppKit
					过程
						main ...
						→ init ...
						→ Window
						→ Render

				SwiftUI
					作用：macOS 原生桌面界面

				COM

					Kite 中：Shell 菜单、剪贴板、拖放
				Shell

				WPD

	04 GPUI 编程模型
		主题概览
			一句话定位
				GPUI 的核心写法是：Entity 存状态，Context 改状态，Render 画界面，Action 和 Subscription 接事件。
			学完能回答
				为什么状态变化会引发重绘？页面之间如何通信？
		Entity 与 Context
			Entity<T>：可观察状态对象
				Entity<T>
					作用：保存可观察状态并允许安全更新
					Kite 中：页面、输入框、表格和 Agent 面板
			Context<T>：update / notify / spawn / subscribe
				update
					作用：修改 Entity 状态
					Kite 中：点击、菜单、异步结果回写
				notify
					作用：请求界面重绘
					Kite 中：状态变化后刷新视图
